# Include code output in a page or quiz

A code block in a page or quiz can pull in a script's own source and
what it produces when run, instead of you pasting either in by hand --
keeping the coursework and the code it's demonstrating in sync. This
is currently Python-specific (`python/rules.inc`); a second language
would get its own `rules.inc` fragment alongside it, generating the
same kind of `.out`/`.stout`/`.crash` artifact.

## Basic usage

````markdown
```python {include=demo.py output=true}
```
````

renders the syntax-highlighted contents of `demo.py`, a "Taken from:
demo.py" download link, and the script's captured stdout. With the
Makefile from [start a new project](new-project.md) (which includes
`python/rules.inc`), `demo.out` is generated by actually running
`demo.py` -- nothing to write by hand beyond the code block attribute
itself.

## Attributes

- `include=<file>` -- the source file to render. Required for anything
  below to do something.
- `output=true` -- run `<file>` as a plain script; show its captured
  stdout under an "Outputs:" label.
- `stout=true` -- run `<file>` as if typed at an interactive Python
  REPL instead; show the transcript (`>>> ` prompts included) under a
  "Prints:" label. Different from `output=`: it's a REPL session, not
  a script's stdout.
- `crash=true` -- `<file>` is *expected* to crash; builds its
  traceback as a `.crash` artifact and renders it under a "Crashes:"
  label, instead of failing the build the way an unexpected crash
  would.
- `hide_crash=true` -- builds the same `.crash` artifact as `crash=`,
  but doesn't render the "Crashes:" section. For a question or page
  that asks "will this code crash?" without answering itself in the
  same breath.

Any combination can appear on one code block (source is always shown;
`output=`/`stout=`/`crash=` each add their own section below it).

## Works the same in a quiz

The same attributes work in a `.quiz.md` question's code blocks -- see
[write a quiz](write-a-quiz.md) and
`dev/sample-course/question-types-quiz.quiz.md` for a worked example
(Questions 4-6 there specifically compare `include=` with and without
`output=`/`crash=`).

## Preview without Canvas

`code-include-filter` resolves the same attributes with no Canvas API
access at all, for `make full`/`make quiz-full` -- see
[write a page](write-a-page.md#standalone-preview-no-canvas-access).
